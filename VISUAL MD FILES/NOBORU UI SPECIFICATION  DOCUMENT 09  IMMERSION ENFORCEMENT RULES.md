NOBORU UI SPECIFICATION

DOCUMENT 09

IMMERSION ENFORCEMENT RULES

Version 1.0

⸻

PURPOSE

This document exists to protect the core vision of Noboru.

The previous documents define:

* what systems exist
* how progression works
* how the world behaves
* how lessons function

This document defines a higher level rule:

Every feature must remain part of the world.

If a feature breaks immersion, it must be redesigned.

This document takes precedence over convenience.

This document takes precedence over common mobile app design patterns.

This document takes precedence over generic game UI conventions.

⸻

THE GOLDEN RULE

At all times the player should feel:

“I am travelling through a living mountain world.”

The player should never feel:

“I am navigating menus inside an educational application.”

Every design decision must support this illusion.

⸻

THE PHYSICAL LOCATION TEST

Every screen must answer one question:

Where is the player physically?

If the answer is unclear:

The screen must be redesigned.

Examples:

Journey → On the mountain trail

Camp → At the campsite

Shop → Visiting a merchant

Inventory → Opening a backpack

Achievements → Visiting a shrine

Memory Book → Reading a journal

Profile → Reviewing a travel record

Events → Discovering a festival

Collections → Viewing collected artifacts

Rewards → Receiving an item from the world

If a screen has no physical location:

The screen fails the immersion test.

⸻

THE WORLD FIRST RULE

The world is the product.

The UI is support.

The world must always remain visually dominant.

The UI must never become the primary focus.

When deciding between:

More world

or

More interface

Always choose more world.

⸻

THE UI TRANSPARENCY RULE

The best UI is invisible.

The player should focus on:

the trail

the fox

the camp

the lessons

the environment

not the interface itself.

If the player notices the UI more than the world:

The design is failing.

⸻

THE APP TEST

Every screen must pass the App Test.

Ask:

“If all artwork was removed, would this still look like a normal mobile app?”

If the answer is yes:

The screen is incorrectly designed.

Noboru should not rely on artwork alone to create immersion.

The structure itself must support immersion.

⸻

THE DASHBOARD BAN

Noboru is not a dashboard.

Never design screens around:

statistics

metrics

graphs

optimization

efficiency

administration

management

⸻

FORBIDDEN DASHBOARD PATTERNS

Do not use:

analytics pages

performance dashboards

activity dashboards

large statistics hubs

productivity interfaces

business intelligence layouts

report screens

data-heavy summaries

If information must be shown:

Present it as part of the journey.

Never as a dashboard.

⸻

THE MENU BAN

Menus should rarely feel like menus.

Whenever possible:

replace menus with locations

replace buttons with objects

replace categories with discoveries

replace lists with environments

⸻

THE PHYSICAL OBJECT RULE

Whenever possible, systems should originate from physical objects.

Examples:

Quest System → Quest Board

Rewards → Chest

Achievements → Shrine

Memory Book → Journal

Shop → Merchant

Streaks → Shrine

Events → Festival Area

Companion Cosmetics → Fox Interaction Area

The player should interact with objects.

Not interfaces.

⸻

THE INVENTORY RULE

The inventory is not a database.

The inventory is not a spreadsheet.

The inventory is not an RPG grid.

The inventory is a traveler’s backpack.

The player should feel like they are browsing belongings.

Not managing data.

⸻

THE SHOP RULE

The shop is not ecommerce.

The shop is not a storefront.

The shop is not a catalog.

The shop is a merchant encounter.

Items should feel discovered.

Not purchased from a website.

⸻

THE PROFILE RULE

The profile is not a social media page.

The profile is not an account page.

The profile is a travel record.

The player should feel like they are reviewing their journey.

⸻

THE STATISTICS RULE

Statistics exist only to support motivation.

Statistics must never dominate the experience.

Statistics should feel secondary.

If statistics become the primary purpose of a screen:

The design has failed.

⸻

THE JOURNEY PROTECTION RULE

The Journey is sacred.

Nothing may replace the Journey.

Nothing may compete with the Journey.

Nothing may become more important than the Journey.

The player should always feel:

The mountain is the destination.

⸻

REGION OVERVIEW RESTRICTIONS

The Region Overview is not a world map.

The Region Overview is not a chapter select.

The Region Overview is not a progression menu.

The Region Overview exists only as a supporting navigation aid.

The trail remains the primary experience.

Always.

⸻

THE FOX RULE

The fox is a companion.

Not a mascot.

Not a UI widget.

Not an assistant.

Not a notification system.

The fox must always feel like a living creature.

The fox should exist within the world.

Never inside the interface.

⸻

THE REWARD RULE

Rewards must originate from the world.

Examples:

Chest opens

Shrine activates

Lantern ignites

Fox reacts

Merchant rewards player

The player should feel rewarded by the world.

Not by a software system.

⸻

THE ACHIEVEMENT RULE

Achievements should feel discovered.

Not unlocked.

Achievements should feel earned.

Not granted.

Achievements should feel ceremonial.

Not transactional.

⸻

THE IMMERSION HIERARCHY

When conflicts occur:

1. World Immersion
2. Atmosphere
3. Emotional Experience
4. Clarity
5. Efficiency

Efficiency is never the primary goal.

Immersion is.

⸻

THE REDESIGN TRIGGER

Immediately redesign a screen if it resembles:

A dashboard

A spreadsheet

An admin panel

A productivity tool

An ecommerce site

A social media profile

A mobile game lobby

A chapter select screen

A traditional inventory grid

A statistics portal

A reporting interface

⸻

FINAL IMMERSION CHECK

Before implementing any feature ask:

Where is the player?

What object are they interacting with?

How does this exist within the world?

Would this still feel immersive if the artwork was removed?

If any answer is unclear:

Redesign the feature.

⸻

FINAL RULE

Noboru is not a language learning application with game elements.

Noboru is a mountain journey that happens to teach Japanese.

Every screen.

Every interaction.

Every reward.

Every animation.

Every system.

Must reinforce that truth.

⸻

END OF DOCUMENT
